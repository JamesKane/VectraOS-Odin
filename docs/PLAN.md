# VectraOS-Odin: the parallel rewrite plan

_Draft, 2026-10-03._

VectraOS-Odin is a clean-room re-implementation of [VectraOS](https://github.com/JamesKane/VectraOS) in Odin. The C23 tree stays the reference implementation; this tree rebuilds the same system, milestone by milestone, and proves equivalence by behaviour: the same QEMU scenarios, the same serial output, the same wire and disk formats.

Upstream says Odin is "community tier; never in the base system" (upstream 04 §1, ADR-0005). This tree does not change that policy. It is a separate project with its own ADRs (ADR-0002).

## 2. Clean room, behaviour only (ADR-0002)

The contracts were **copied once** at the reference commit and are now this tree's own:

| Copied | Where | Role |
|---|---|---|
| `abi/vx/{syscalls,rights,status}.def` | `abi/vx/` | The ABI tables. `build` generates Odin from them ("one table, one truth") |
| `tests/qemu/*.ndb` (33 scenarios) | `tests/qemu/` | **The acceptance oracle.** Expected serial text, prompts, error strings |
| The format and protocol specs (9Px, ring layout, ndb, bootfs tar, `vxfs` volume) | read from upstream's docs, re-specified here as each lands | Wire and disk formats must match byte for byte |

There is no submodule and no mixing of C and Odin components in one image. Anything observable (serial text, error strings, `/proc` layout, wire bytes, disk format) matches upstream. Anything else is free to be idiomatic Odin. An intended observable difference needs a divergence ADR.

Tracking upstream is manual and deliberate: at each milestone boundary, read upstream's commits since the last reference, record them in `docs/PORTING.ndb` and re-copy changed scenarios.

## 3. Language and safety (ADR-0003)

Odin replaces C23 for all first-party code, kernel included. Assembly stays for entry points, context switch and exception vectors, assembled by clang. Vendored code (Limine, musl, Lua, sbase, compiler-rt) stays C, built by clang, and is never rewritten.

| Upstream C rule | Odin |
|---|---|
| Unity builds | One package per component |
| Zero is initialisation; `vx_str`, `vx_bytes` | Native: zero values, `string`, `[]u8` |
| No general allocator in the kernel; arenas in user space | Kernel: `-default-to-nil-allocator` plus typed pools charged to budgets. User space: `context.allocator` is an arena |
| `[[nodiscard]]` on kernel and authorization paths | `@(require_results)`, `or_return` |
| `ckd_add`, `ckd_mul` on every foreign size | `intrinsics.overflow_add`, `overflow_mul` behind `ckd` helpers |
| X-macro `.def` tables | Odin source generated by `build` from the same `.def` files |
| `#embed` | `#load` |
| `static` | `@(private="file")` |
| `-Werror -Wshadow` | `-vet -vet-shadowing -strict-style -warnings-as-errors` |
| UBSan trap in the debug kernel | Bounds checks on everywhere, failure procs routed to `panic` |
| ASan and UBSan host tests | `odin test -sanitize:address` |
| libFuzzer harnesses | Odin built as an object, linked into libFuzzer |

**Lost**, recorded in ADR-0003: kcfi, branch protection and CET, the clang static analyzer, clang-tidy, and compiler-enforced "no recursion in the kernel" (a later call-graph check over `-build-mode:llvm-ir` can restore it).

**Frame pointers.** Panic backtraces and `dbg` need them in every function, leaf functions too. Odin has no flag for them, so every first-party build goes Odin → LLVM IR → `llc --frame-pointer=all` → `ld.lld` (spike S2, ADR-0003).

## 4. SIMD in the kernel (ADR-0004)

Upstream's kernel is `-mgeneral-regs-only`. Odin's freestanding runtime and codegen use SSE and NEON (a trivial kernel object holds 571 vector instructions on x86_64 and 939 on aarch64), so the Odin kernel supports vector state instead of banning it:

- FP and SIMD are enabled in the assembly entry, before the first Odin instruction, on every CPU.
- The kernel's ISA is pinned to a bounded baseline (x86-64-v3 without AVX-512; ARMv8 NEON without SVE or SME), so the kernel's own save area has a fixed size.
- Every entry from user space (syscall, IRQ, exception) saves user vector state eagerly. Nested IRQs save the kernel's.
- Per-thread save areas come from a typed pool charged to the thread's budget, sized from CPUID leaf 0xD on x86_64, 64-byte aligned.
- Lazy save is a later optimisation, behind a benchmark.

## 6. Phases

Each phase is gated by upstream's scenarios for the milestone it reaches.

**P0. Spikes and foundation.** Each spike is go/no-go. All five passed on 2026-10-03: see [spikes/RESULTS.md](../spikes/RESULTS.md).
- **S1:** a freestanding Odin kernel object, linked by ld.lld with a linker script and booted by Limine to a serial "hello" on both architectures. This includes setting up Odin's `context` at the assembly-to-Odin boundary.
- **S2:** frame pointers in every function (§3).
- **S3:** SIMD enable, eager save and restore across a trap, and a test that corrupts vector registers across traps (§4).
- **S4:** `build` generates the ABI enums from `abi/vx/*.def`.
- **S5:** kernel build time against upstream's 1 s budget.
- Foundation: `build.odin` (`all`, `image`, `qemu`, `test`, `check`, `loc`, `vendor-check`), Limine vendored and built by `build` (spikes use Homebrew's Limine meanwhile), the scenario runner over the serial console.

**P1. M1, first light.** Limine requests, early serial, GDT/IDT and vectors, the physical allocator, paging and HHDM, object pools, LAPIC/TSC and GICv3/generic timer, panic with backtraces, SMP. Task, Thread, Vmo, `as_map`, Port, `handle_close`, `debug_write`; the ELF loader and an `svcd` stub. Gate: `boot` (M1 form), `panic`, `phys`, `timer`, `smp`, `lower-half`, `stack-overflow`.

**P2. M2, a shell in a namespace.** Kernel: channels, rings, counters, futexes, handle transfer, IRQ objects, physical VMOs, `task_create` from a spawn message. Libraries: `vx-ring` with `vx-check` (the model checker), `vx-9p`, `vx-ns`, `vx-ndb`, `vx-tar`, `vx-utf`, `vx-rt`. `bootfs`, the UART drivers, `svcd`, `procfs`, `gsh` and the commands. Gate: `shell`, `ns`, `proc`, `cons`, `ktest`.

**P3. M3, mount the network.** ACPI, MSI, DMA domains, the PCI scan in `devmgr`; virtio-pci and `drv-virtio-net`; `vx-net` (Ethernet, ARP, IPv4, ICMP, UDP, DHCP, TCP, DNS) and `netd`; 9P over TCP; `vx9pserve` as an Odin host tool. Gate: `net`, `netd`, `tcp`, `mount`, `u9fs`, `pci`, `iso`.

**P4. M4, POSIX and debugging.** Namespace groups and `nsd`, notes and exit strings, `ptyd`, the in-task fault path, `vx-rc`, `vx-debug` (DWARF, evaluator, aarch64 disassembler; it must also read Odin's own DWARF), `dbg`, the `procfs` debug files. The musl back end (`ports/musl/vx`) is written in Odin as an object with C-ABI exports linked into `libc.a`, or kept as a small C exception by ADR; decided at the start of P4. Gate: `posix`, `rc`, `rcscript`, `sbase`, `lua`, `dbg`.

**P5. M5, storage**, chasing upstream: the `block` class, virtio-blk, GPT, `vx-fs` and `fsd`, the pager and `dref`. Gate: `block`, `fsd*`, plus a cross-format test: the Odin `fsd` reads volumes the C `fsd` wrote, and the reverse.

**Then** port upstream step by step as it lands.

## 7. Work streams

Once P0's spikes pass:

- **A. Kernel:** P1 → P2 → P3 kernel work.
- **B. Host-testable libraries:** `vx-utf`, `vx-ndb`, `vx-tar`, `vx-sha256`, `vx-gpt`, `vx-ring`, `vx-check`, `vx-9p`, `vx-ns`, `vx-net`, `vx-rc`, `vx-fs`, `vx-debug`. These have no kernel dependency and can run ahead of the kernel. Each ports upstream's `tests/host/*` and fuzz corpora as its oracle.
- **C. Build and CI:** `build.odin`, the scenario runner, the macOS × Fedora × {x86_64, aarch64} × {debug, release} matrix.
- **D. User services:** start when `vx-rt`, `vx-9p` and `vx-ns` land.

## 8. Risks

- **Upstream velocity.** Re-reference only at milestone boundaries.
- **Odin freestanding maturity:** runtime assumptions, `context` in interrupt paths, bounds-check failure paths in the kernel, no inline assembly (more `.S` stubs, or `intrinsics.syscall` where the register convention fits).
- **The safety tooling lost** (§3).
- **Kernel entry cost from vector state** (§4). `./build bench` keeps it visible.
- **Odin ships monthly dev releases.** The pin moves only by amending ADR-0001.
