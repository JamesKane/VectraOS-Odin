# ADR-0009: Lua 5.5.1, vendored unchanged, as `/bin/lua`

Status: accepted, 2026-10-04. The import was reviewed by James Kane, 2026-10-04 (`third_party/VENDOR.ndb`).

## Context

Upstream's M4 puts Lua in the POSIX userland, and one of the M4-era scenarios this tree is judged by runs a Lua script there (`tests/qemu/m4/lua.ndb`, on `tests/user/luatest.lua`). Lua is about 30 kLOC of portable C with no dependency but a C library, so it is the first program built against `vectra-musl` (ADR-0007) that VectraOS did not write. Upstream made the import in its ADR-0015.

## Decision

- **Lua 5.5.1** (2026-07-24) is vendored unchanged under `third_party/lua`: the whole release tree (`src`, `doc`, `Makefile`, `README`). The tree was copied from upstream VectraOS's vendored copy at `002a9a8`; it is Lua's code, not upstream VectraOS's, so ADR-0002's clean-room rule does not apply to it. Licence: MIT.
- **Provenance.** Lua's releases are not signed. The tarball's sha256 is the one lua.org publishes; on 2026-10-04 the tarball was fetched again from lua.org over HTTPS, its sha256 matched `VENDOR.ndb`, and its tree was identical to the vendored one. Upstream also compared every source file with the `v5.5.1` tag of `github.com/lua/lua` (all identical, `luac.c` aside, which only the release has). When reviewing, confirm the checksum against a second fetch, and compare against the tag.
- **The build** is `tools/build`'s, from `ports/lua/port.ndb`: the source set and flags of Lua's `src/Makefile` for its `posix` platform (`-std=gnu99 -O2 -Wall -Wextra -DLUA_USE_POSIX`), with frame pointers kept, as for musl. The sources are compiled once per architecture and cached (`out/lua/<arch>`); `lua.c` is linked with them and the `vectra-musl` sysroot, statically, into `out/<arch>/<mode>/bin/lua`, which is to be `/boot/bin/lua`. Not `LUA_USE_LINUX`, which adds `dlopen`: C modules are built in or absent. Not `luac` until something precompiles chunks.
- **Ports' programs**: a port's `program=` records name programs built from its `sources=` and their own. sbase (ADR-0010) uses the same records.
- **Not in an image yet.** Lua links only once musl's back end exists (ADR-0007); until then `./build all` compiles it and does not link it. The image, and the script tests the Lua scenario needs (a manifest and a script with no program of their own), come with the back end.

## Known limits

- `os.execute` and `io.popen` run `/bin/sh -c`, and there is no `/bin/sh`. They fail cleanly.
- `os.time()` counts from boot, as `CLOCK_REALTIME` does until there is a wall clock.

## Consequences

- Upgrading is replacing the tree with the next release's and checking `src/Makefile`'s lists and flags against `port.ndb`.
- Lua's code is not under the house rules; it builds with its own flags and warnings.
