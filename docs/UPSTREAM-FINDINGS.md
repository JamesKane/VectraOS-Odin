# Upstream findings

Bugs the port found in upstream VectraOS, behaviour this tree deliberately does differently, and why. Each is worth reporting upstream.

Upstream verified the rows of this table and fixed them in its `ab83fe6` and `f24356f` ("Fixes from the Odin port's findings", M6 step 6b), and `01ced6c` fixed the pager row's SIGBUS mapping; a row's "Where upstream" names the commit that fixed it. Where upstream fixed a row differently from this tree, this tree now does as upstream does (the "Here" column says what changed); the rows still open are the aarch64/x86_64 unwinder cases (upstream: a known gap, its M14) and the not-a-bug rows.

| P2 clean-up | `kernel/obj/device.c` (M2) | `iorange_create` accepts a 65,536-port range (`end > 0x1'0000`) and stores its count in a `uint16_t`: 0, so the task gets no ports while the console is still handed off. | Fixed in this tree before upstream's M3 fixed it the same way (`count` as 32 bits). |
| P3 | `lib/vx-ns` (M3; fixed upstream in `002a9a8`, tested since `f24356f`) | Unmount lets a connection go once no *mount* uses it, even while a *bind* still holds a fid on it; the next walk through that bind follows a null client and crashes. | Any member, mount or bind, keeps the connection, as upstream's fix does.
