# Upstream findings

Bugs the port found in upstream VectraOS, behaviour this tree deliberately does differently, and why. Each is worth reporting upstream.

| Found | Where upstream | What | Here |
|---|---|---|---|
| P2 clean-up | `kernel/obj/device.c` (M2) | `iorange_create` accepts a 65,536-port range (`end > 0x1'0000`) and stores its count in a `uint16_t`: 0, so the task gets no ports while the console is still handed off. | Fixed in this tree before upstream's M3 fixed it the same way (`count` as 32 bits). |
| P3 | `lib/vx-ns` (M3) | Unmount lets a connection go once no *mount* uses it, even while a *bind* still holds a fid on it; the next walk through that bind follows a null client and crashes. | Any member, mount or bind, keeps the connection. Found by comparing random namespace scripts against upstream's C. |
| P3 | `kernel/arch/*/arch.c` (M3) | Not a bug: M3 makes FP/SIMD trap in user tasks until the kernel saves it. | ADR-0004: saved eagerly at every entry, so user tasks have it; ktest checks that it works where upstream checks that it faults. |
| P3 | `servers/netd/netd.c` (M3) | A query's answer is held in 256 bytes and cut there, silently: `/net/dns` for a name of more than 236 bytes (names may have 253) answers with a line cut short, its address truncated and no newline, and with four addresses, names of more than 44 bytes overflow it. | Kept as upstream does it, byte for byte (the answer is built whole, then its first 256 bytes kept); a fix would size the answer for `DNS_ADDRS` lines of the longest name. |
| P4 | `lib/vx-rc/rc.c` (M4) | A pipeline stage with a file redirection: the redirection's path is freed as the redirection is undone, but the stage runs afterwards, so the host reads the path from freed heap memory. Found by cross-checking a million mutated scripts against upstream's C. | The path is freed with the deferred close, after the stage has run. |
| P4 | `lib/vx-debug/eval.c` (M4) | A pointer difference divides by a type size the target supplies; a hostile size of 2^64−1 traps (SIGFPE) in the debugger. | The division wraps. |
| P4 | `lib/vx-debug` unwinder (M4) | x86_64: past `push %rbp` the frame record is assumed at sp, wrong after callee-saved pushes before `prologue_end`. aarch64: an outer frame's sp is taken as fp+16, so SP-relative locals are read from the wrong place. | Kept, for byte-for-byte output; a host test documents the aarch64 case. |
| P4 | `kernel/arch/*/arch.c`, `kernel/obj/exception.c` (M4 step 2c) | Not a bug: M4 keeps each thread's FP/SIMD registers in its thread object, saved with FXSAVE (or q0-q31) at each switch, and a stopped thread saves them for a debugger (`user_held`). | ADR-0004's design stays: the state is saved at every entry, in the trap frame (XSAVE, AVX included, on x86_64), so a stopped or suspended thread's registers are always there. `.Get_Fpregs`/`.Set_Fpregs` read and write that area in place: on x86_64 the XSAVE area's legacy region, which is FXSAVE's image, with a component XSAVE left in its initial state (XSTATE_BV clear) written out as such, and a set marking x87 and SSE present; the YMM upper halves are not in a `vx_fpregs` and are left as they were. MXCSR, FPCR and FPSR are made safe as upstream makes them. Only the thread pointer is saved at each switch, as upstream does. |
| P4 | `lib/vx-rt/note.c` (M4 step 4e) | Not a bug: the in-task note entry saves FP/SIMD state with FXSAVE, which upstream's x86_64 user state is (it never enables AVX). | Here user code may use AVX (ADR-0004), so the x86_64 entry saves with XSAVE, every component XCR0 enables, in 4 KiB of the thread's stack. |
| P4 | `lib/vx-note/note.c` (M4) | Not a bug: `vx_trap_note`, Plan 9's words for a trap, is a header both the kernel and vx-rt include. | It is `vx.trap_note` in `abi/vx/note.odin`, which the kernel and `vx:rt` both import, as the text is part of the interface (a parent reads it as the exit string). Checked against upstream's C on the host: 864 cases (every kind, code 0-3, six addresses, three pcs), byte for byte. |
| P4 | `lib/vx-rt/rt.c` (M4 step 4e) | Not a bug: `vx_main` returns its exit string. | `vx_main` still returns an int here, until the programs are ported to M4: 0 ends the program with the empty string, anything else with its decimal value, as APE's `exit(n)` does. `rt.exits(msg)` ends it with a string. |
| P4 | `kernel/boot.c` (M4 step 3e) | Not a bug: the kernel asks Limine for five entropy values, the first for its stack protector's guard. | It asks for four, all for the root task's `entropy=` record: Odin's code has no stack protector. |
| P4 | `kernel/sched/sched.c` (M4 step 4c) | Not a bug: `vx.hangdump=N`, a debugging aid that prints every thread N seconds after boot. | Not ported. |
| P4 | procfs's debug path with a musl program (M4) | Not a bug upstream, which only debugs vx-rt programs: a musl program's signal handler, declining a fatal fault, runs the instruction again (its `vx_note_crash`), and the kernel offers the debugger that fault a second time, so the crash never reaches procfs's crash directory while a debugger is attached. Here `dbgdemo` runs on musl (ADR-0007). | procfs passes on, without a second stop, a fault identical to the one it just passed on for that thread. |
| P5 | `lib/vx-fat` `fat_dir_next` (M5) | A long-name slot numbered 0 with a matching checksum writes 26 bytes before a stack buffer (ASan: stack-buffer-underflow); a hostile disk triggers it. | Such a slot forms no name. |
| P5 | `lib/vx-fat` (M5) | Twenty long-name slots of characters at U+0800 and above decode to 780 bytes, overrunning `fat_entry.name[766]` into `alias`. | The name buffer holds 780 bytes. |
| P5 | `lib/vx-fat` `fat_write` (M5) | The `offset + count > UINT32_MAX` check wraps near 2^64; the gap loop then zero-fills the volume. | Overflow-checked. |
| P5 | `lib/vx-iso` `iso_record_at` (M5) | The next offset and the padding skip are 32-bit: a directory extent near 4 GiB wraps them and `iso_dir_next` loops forever, so a hostile image hangs isofs. | 64-bit offsets. |
| P5 | `lib/vx-iso` `iso_sector` (M5) | A failed read leaves the evicted cache slot valid under its old sector; a partial read caches corrupt data as that sector. | A slot whose read failed is marked invalid. |
| P5 | `lib/vx-driver` `blkclient.c` (M5) | A driver reporting a sector larger than the 1 MiB arena gives `max == 0`, and reads and writes loop forever on zero-length requests: a broken driver hangs fsd. | Refused with `Err_Unsupported`. |
| P5 | `lib/vx-iso` (M5) | `iso_each_su` and `iso_decode` keep function statics, so they are not reentrant (harmless in isofs today). | No statics. |
| P5 | `build.c` (M5 steps 6c, 6d) | Not a bug: from M5 upstream's runner gives every scenario the machine's IOMMU (q35's intel-iommu, virt's `iommu=smmuv3`) and its virtio devices `iommu_platform=on`. | The m5/ scenarios get it (and `iommu=caching`, VT-d's caching mode, as upstream); M4's scenarios (`tests/qemu/m4/`) run without one, as M4's runner ran them, so the M4 gate is judged as it was. |
| P5 | `tests/kernel/ktest.c` (M5 step 6d) | Not a bug: the check that a DMA mapping's device addresses are contiguous from 4 GiB is unconditional, since upstream's runner always has an IOMMU. | ktest makes it where the firmware describes an IOMMU (a DMAR table, or an IORT with an SMMUv3 node: virt always has an IORT, for its ITS), so m4/ktest still passes; m5/ktest makes it on both architectures. ktest also checks `system_power`'s refusals and `clock_set`, which upstream's does not. |
| P5 | `kernel/obj/exception.c` (M5 step 5a) | Noted: a pager's late page is `VX_EXCEPTION_PAGER_TIMEOUT` ("page not supplied") only to a debugger, an in-task handler or an exception port. A task no one handles it for is killed by the architecture's default with the original page fault's words ("sys: trap: fault read addr=…", the unaligned address), since the kind changes only inside `exception_raise`. | Kept, for the same exit strings. |
| P5 | `lib/vx-fs/blk.c` `vxfs_log_compress` (M5) | When `arena_take` fails (the arena full), the failed slot (address 0) is still counted; cleanup frees address 0 into the free ranges and decrements `used`. The volume has failed by then, so nothing more is written. | The failed slot is not counted. |
| P5 | `host/vxfs` `make_users` (M5) | `snprintf` into `text[256]`, but `vxfs_write` writes the untruncated length: a `-u` name of ~230 bytes or more reads past the stack buffer. | Lengths kept to what was written. |
| P5 | `tests/fuzz/vxfs_fuzz.c` (M5) | The "whole log block" path still stamps the block with the pre-step-10 hash (header not included), so it can never load: dead since M5 step 10. | Ported as upstream has it; noted. |
| P5 | `build.c` `iso_mangle` (M5 step 8c) | A file's ISO 9660 name is formatted into `char out[32]` with `snprintf`, but name, dot, extension and ";1" can come to 32 characters: a base of 26 or more before a three-letter extension loses the version's "1" ("A_LONG_MIXED_CASE_NAME_THA.TXT;" in the test ISO). Readers that go by Rock Ridge or Joliet never see it. | Kept, cut at 31 bytes as upstream's buffer cuts it, so the ISO is upstream's byte for byte (tests/host/iso checks it). |
| P5 | `build.c` `iso_volume` (M5 step 8c) | Not a bug: the copyright, abstract and bibliographic identifiers are padded as one 111-byte field, so in the Joliet descriptor the UCS-2 pairs run across the fields' boundaries. | Kept (one `file_ids` field), for the same bytes. |
| P5 | `servers/dosfs`, `servers/isofs` (M5 steps 8a-8c) | Not a bug: the programs' state is static and starts zeroed. | Here `start` resets it first, so the host tests (tests/host/dosfs, isofs) can start a program several times in one process, on a fake kernel and block device (tests/host/blkfake). Upstream has no host test of either server. |
| P6 | `lib/vx-guide` `guide_cell` (M6 step 6a1) | A table cell is rendered into 512 bytes, then cut "on a whole rune" with `vx_utf_cut(p, n, n)`, whose limit is the text's own length, so it never cuts: a cell of more than 512 bytes whose 512th byte falls inside a rune renders the page as invalid UTF-8, what upstream's own guide_fuzz.c aborts on. Found by the cross-check (a 601-byte cell). | Cut on a whole rune (tests/host/guide `test_long_cell`); every other rendering is upstream's byte for byte. |
| P6 | `lib/vx-guide` (M6 step 6a1) | Not a bug: `vx_guide_open`, `guide_directive`, `guide_widths` and `vx_guide_render` keep their 4 KiB records and parser in function statics, so two pages cannot be read at once. | No statics: they are locals (the parser and a record, a few KiB of a 256 KiB user stack). |
| P6 | `build.c` usage (M6 step 6a3) | Not a bug: a program's usage message is a generated C header, `-include out/gen/usage/NAME.h`, defining `VX_USAGE`. | A generated Odin package, `out/gen/usage/NAME/usage.odin`, imported as `gen:usage/NAME` (`usage.TEXT`); the check requires the import and no `"usage:` string of the program's own. |
| P6 | `build.c` `check_man` (M6 step 6a2) | Not a bug: the host tools are `host/*`, the 9Px messages `lib/vx-9p/messages.def`'s rows, and pages and index records come in `readdir` order. | The host tools are `tools/*` but `build` (counted as `build`, as upstream's) and `abigen` (a part of `./build`, which runs it first; upstream expands the tables in build.c); the messages are `vx:p9`'s `MESSAGES` table, which tests/host/p9_codec checks against messages.def; pages are taken in byte order of their names, so the image and the index are the same on every host (`lookman` lists matches in index order). The inventory is upstream's name for name, so `man/missing` is upstream's unchanged. |
| P6 | `man/*/*` `src=` (M6 steps 6a1-6a5) | Not a bug: a page's SOURCE names upstream's files (`cmd/man.c`, `lib/vx-guide/guide.c`). | Kept: the pages are contracts, copied unchanged, since `man`'s output must be upstream's byte for byte. |
| P6 | `lib/vx-rc` `rc_compile_tree` (M6 step 6a6a) | A command popped with the compile stack one short of full pushes its end marker into the last place, then its next phase unchecked, past the static `items[1024]`; past that the `ni == RC_CITEMS` checks never hold, so a deeper nest writes further. ASan: global-buffer-overflow at ``echo a^`{echo x}`` and 1019 more carets. | Refused, "nested too deeply", when the command's next phase would not fit. |
| P6 | `lib/vx-rc` `rc_pop_redirs` (M6 step 6a6b) | Undoing a here document's redirection calls the host's close with handle 0 (its `rc_fd` has none): `cmd/rc` closes whatever file holds slot 0, e.g. the block's own output in `{ cat <<EOF ...; echo y } > out`, so `y` is lost. | No close for a here document. The cross-check's oracle is patched to match (one condition), and api_test checks it. |
| P6 | `lib/vx-rc` `rc_pop_redirs` (M6 step 6a6b) | A pipeline stage's here document text is freed when its redirection is undone, before the pipeline runs: the host feeds freed heap memory (`cat <<EOF \| wc` gives `cat` the bytes of the next stage's words, `wc\0\0\0\0`). | Kept until the stage has run, as file paths are (P4); the cross-check does not read a stage's here document, and api_test checks it. |
| P6 | `cmd/rc.c` `relay_run` (M6 step 6a6b) | A here document on an output descriptor (`echo x <<[1]EOF`) is relayed as a file with handle 0: the command's output is written into whatever file holds slot 0. | Not relayed out: the output is dropped. |
| P6 | `lib/vx-rc` `rc_builtin` (M6 step 6a6c) | `exit a b` writes its usage message with a length of 34 for its 36 bytes: `Usage: exit [status]\nExiting anywa`, no newline. | Kept, byte for byte. |
| P6 | `lib/vx-rc` `rc_rdcmds` (M6 step 6a6b) | Not a bug: a compile that has no memory to parse leaves `incomplete` as the attempt before set it, so a reader may go on to "unexpected end of file" rather than stop for memory. | Kept: `compile_text` leaves its `incomplete` as it was in that case. |
| P6 | `kernel/obj/task.c` `task_query` (fixed upstream in M6 step 6b, `89b3ce8`) | `as_query` on an ended task walked its freed mapping table and faulted the kernel. | This tree never faulted (it checked for the table) but answered `Err_Not_Found`; it answers `Err_Bad_State` now, as upstream does, and ktest checks it. |
| P6 | `kernel/obj/exception.c` `exception_resume` (fixed upstream in M6 step 6b, `89b3ce8`) | Any stop was answered with MANAGE on the task, a debugger's first-chance stop included. | The same bug was here; ported as upstream fixed it: DEBUG for a stop at the debugger's port, MANAGE for one at the exception port, and the stop answered must still be the one the rights were checked for. |
| P6 | `build.c` `realloc_words` (M6 step 6b) | Not a bug in practice: the buffer for a fence's `VX_USAGE_word` lines is sized `fence.len * 6 + 256`, but each distinct word costs some 60 bytes of declaration besides its line, so a fence of short distinct words (seven or so lines like `ab`) writes past it into the build tool's bump arena, over memory not yet handed out. rc(1)'s fence needs 888 bytes of its 2,014. | Odin strings, no fixed buffer: `TEXT_word` constants in `gen:usage/NAME`. |
| P6 | `build.c` usage (M6 step 6b) | Not a bug: rc's builtins take their usage messages from rc(1)'s fence as `VX_USAGE_bind` and the like, generated for any fence word that is a C name. | `usage.TEXT_bind` and the like, in the same generated package as `usage.TEXT`. |
| P6 | `.def` key tables (M6 step 6b) | Not a bug: each parser `#include`s its format's `KEY()` table into a `const char *const[]`. | `tools/abigen` expands each table into `NAME_keys_gen.odin` beside its parser (`NAME_KEYS`), as it expands the ABI's; `ndb.unknown_key` returns `(key, ok)`. The `.def` files are upstream's, unchanged. |
| P6 | `lib/vx-rc` (M6 step 6a6) | Not a bug: the host's descriptors, notes and builtins are C's (`rc_fd` kinds, `rc_trap(r, sig)` by number, `builtin_names` ending in nullptr, `rc_each_fn` with a callback). | `rc.Fd_Here` carries the text; `rc.trap(r, rc.Sig)`; `Host.builtin_names` a slice; `rc.fns`/`rc.next_fn` an iterator; `Host.read_line` returns 0 at the end or on an error. |
