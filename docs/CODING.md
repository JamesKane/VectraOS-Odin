# Writing Odin for VectraOS-Odin

The rules are ADR-0003's; this is how they look in practice. Read `lib/ndb` and `kernel/phys.odin` as models.

## Layout

- `lib/<name>/`: one package per library (`package <name>`), imported as `vx:<name>` (`-collection:vx=lib`).
- `abi/vx/`: the kernel/user ABI, imported as `abi:vx` (`-collection:abi=abi`). `abi_gen.odin` is generated by `./build` from the `.def` tables; run any `./build` command (or `./build abi`) before compiling by hand.
- `tests/host/<name>/`: host tests for `lib/<name>`, as `package <name>_test`, run by `./build check` under ASan.
- `kernel/`: one package; architecture files end in `_amd64.odin` / `_arm64.odin`; assembly in `kernel/arch/<arch>/*.S`.

## Rules

- **Libraries import only `base:` and `vx:`/`abi:` packages.** No `core:`: there is no Odin OS layer for VectraOS. Tests may use `core:` freely.
- **No implicit allocation.** Libraries take buffers or an explicit arena; they never use `context.allocator`. Kernel code and anything the kernel may share (ring, ndb, utf, tar) is `proc "contextless"` throughout.
- **Behaviour matches upstream byte for byte:** wire formats, on-disk formats, error strings, ndb output. Port upstream's host tests and fuzz corpora as the oracle, and keep their case comments.
- **Zero is initialisation.** Design structs so all zeroes is a valid empty value.
- **Slices, not NUL-terminated strings.** `string`/`[]u8` everywhere; C strings only at the Limine and POSIX boundaries.
- **Every size, offset or count from another task** goes through `intrinsics.overflow_add` / `overflow_mul` before use.
- **`@(require_results)`** on status-returning procedures in the kernel and on authorization paths.
- **`@(private="file")`** for anything not used outside its file.
- **Comments** explain why, in full sentences, as the existing files do. Upstream's comments are a good source; reword them to fit Odin.
- **Format:** tabs, `-strict-style`, `-vet -vet-shadowing`, `-warnings-as-errors`. Every package must also pass `odin check <dir> -no-entry-point -target:freestanding_arm64 -collection:vx=lib -collection:abi=abi -vet -strict-style -warnings-as-errors` (and `freestanding_amd64_sysv`) if the kernel or user space will use it.

## Checking your work

```sh
./build abi
odin test tests/host/<name> -collection:vx=lib -collection:abi=abi -vet -strict-style -warnings-as-errors -sanitize:address
odin check lib/<name> -no-entry-point -target:freestanding_arm64 -collection:vx=lib -collection:abi=abi -vet -strict-style -warnings-as-errors
./build check
```
